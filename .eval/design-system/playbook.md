# Design system playbook

A team-management web app for a football (soccer) side: it tracks seasons (@src/contexts/SeasonContext::SeasonProvider, @src/components/SeasonPicker::SeasonPicker), upcoming and past fixtures (@src/routes/index::UpcomingPage, @src/routes/fixtures.index::FixturesPage, @src/routes/fixtures.$fixtureId::FixtureDetail), player attendance signup (@src/components/AttendancePanel::AttendancePanel), the squad (@src/routes/squad::SquadPage), season statistics (@src/routes/stats::StatsPage) and a 'bødekasse' fines page (@src/routes/bodekasse::BodekassePage). The app shell (@src/routes/__root::RootShell) offers desktop nav links and a mobile bottom tab bar, with authentication via @src/contexts/AuthContext::AuthProvider. The UI is built on a shadcn-style primitive library under src/components/ui, themed through CSS variables in src/styles.css: semantic colour roles (background/foreground t0, t6; card t1, t5; popover t3, t8; muted t2, t7; accent t12, t4; primary t14, t9; secondary t15, t10; destructive t16, t17; warning t18, t11; border t19, input t20, ring t21), two gradients (t13 primary, t31 pitch — used for the lineup-on-a-pitch views), a display and a sans typeface (t22, t23), a radius scale (t24–t28) and card/glow shadows (t29, t30).

## In one screen

- **Theme lives in:** the stylesheet (Tailwind v4, CSS-first, so there is no tailwind.config).
- **Tokens:** 32 in 9 group(s), folded from 55 declaration(s).
- **Themes:** light and dark, switched by `&:is(.dark *)`.
- **Spent:** 32 token(s) are used somewhere; 0 are declared and never used.
- **Components:** 223 declared, 190 primitives, 12 with variants (53 variant value(s)).
- **Disagreements:** 144 instance(s) in 4 kind(s). See the last section.

## Provenance

The primitives are generated by shadcn/ui: `components.json` declares style `new-york`, base colour `slate`, icon library `lucide`, primitives at "@/components/ui", and CSS variables on. A reader who knows that convention knows most of this system before reading any of it.
